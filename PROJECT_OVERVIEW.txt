1. PROJECT DESCRIPTION
================================================================================

The Women Safety App is a comprehensive mobile safety solution designed to 
empower users (especially women) with real-time emergency response capabilities, 
AI-powered risk detection, and guardian network coordination.

VISION: Provide instant emergency assistance through multi-channel alerts, 
        intelligent danger prediction, and seamless guardian coordination.

KEY PROMISE: 9-step automated SOS orchestration that triggers emergency services, 
             guardians, audio/video evidence capture, and live tracking within 
             seconds.

Target Users:
  • Women commuting alone or in high-risk areas
  • Rideshare users (Uber, Ola integration)
  • Users with pre-configured emergency guardians
  • Organizations managing team safety

3. DATASETS & DATA SOURCES
================================================================================

REAL-TIME DATA STORAGE
  
  Firebase Firestore Collections:
    • users — User profiles, emergency contact IDs
    • guardians — Volunteer guardian profiles & ratings
    • sos_alerts — Active/historical SOS incidents with locations & media
    • rides — Uber/Ola ride tracking data
    • guardian_faces — Face recognition training data & embeddings
    • danger_zones — AI-predicted dangerous area definitions
    • location_history — Continuous user location tracking logs
  
  PostgreSQL Relational Tables:
    • users — User profiles & authentication credentials
    • emergency_contacts — Guardian lists per user
    • sos_alerts — Complete incident history
    • location_logs — Historical tracking data
    • danger_zones — Unsafe area definitions
  
  Local Device Storage:
    • SQLite — Offline queue, cached guardians, location history
    • Shared Preferences — Auth tokens (JWT), app settings, widget flags

MACHINE LEARNING DATASETS

  TensorFlow Lite Model (danger_prediction_model.tflite):
    • Training Data: Historical location + crime incident data
    • Features: GPS coordinates, time of day, day of week, SOS incidents
    • Output: Real-time risk score (0-100) for any location
    • Inference: On-device (works offline)
    • Update Frequency: Daily from aggregated user data
  
  Google ML Kit (Face Recognition):
    • Guardian Face Images — Registered by users (multiple angles)
    • Facial Feature Vectors — Vector embeddings for comparison
    • Use Case: Verify guardian identity during SOS
    • Processing: Privacy-preserving on-device (Google ML Kit)
  
  Speech-to-Text Model (Distress Detection):
    • Voice Datasets: Panic markers & speech patterns
    • Keywords: "help", "emergency", "stop", "don't"
    • Features: Pitch analysis, speech speed, emotion detection
    • Output: Distress confidence score
    • Inference: On-device (no cloud dependency)

USER-GENERATED DATA

  Location Data:
    • GPS coordinates (latitude, longitude, accuracy)
    • Update frequency: Every 30 seconds
    • Retention: 90 days raw, 1 year aggregated
    • Shared with: Guardians (during SOS only)
  
  Emergency Contact Data:
    • Guardian names, phone numbers, emails
    • Primary/backup contact priority
    • Relationship type (family, friend, volunteer)
  
  Evidence Media (During SOS):
    • Photos — Automatic capture (JPEG)
    • Audio — 3-second pre-trigger + ongoing recording
    • Video — Optional or automatic (Firebase Storage)
    • Storage: Encrypted with user's encryption key
    • Retention: 30 days (configurable, auto-delete after)
  
  Incident Data:
    • SOS trigger type (button, shake, voice, widget)
    • Timestamp & location coordinates
    • Guardians notified & response status
    • Evidence media URLs & metadata

EXTERNAL DATA SOURCES

  Google Maps API:
    • Map tiles & terrain data
    • Geocoding (address ↔ coordinates conversion)
    • Route calculation & ETA
  
  Google ML Kit API:
    • Face detection models (on-device inference)
    • Facial landmark detection (eye, nose, mouth coordinates)
  
  Agora RTC:
    • Video streaming session metadata
    • Real-time communication channel data
  
  Twilio / SMS Gateway:
    • SMS delivery logs & status
    • Message templates & personalization data
  
  Firebase Admin SDK:
    • User authentication records
    • Cross-platform identity verification
    • FCM push notification metadata

DATA VOLUME & RETENTION

  Data Distribution:
    • Location logs: ~2,880 entries per user daily (30-sec intervals)
    • SOS alerts: Variable (on-demand, ~5-10 per active user/year)
    • Guardian profiles: 100s-1000s (volunteer network scale)
    • Danger zones: 1000s-10000s (city-level coverage)
    • Evidence media: 10-100 MB per SOS incident
    • Face vectors: Per registered guardian (~1-10 per user)
  
  Retention Policy:
    • SOS Alerts: Indefinite (legal & analytics)
    • Location History: 90 days raw, 1 year aggregated
    • Evidence Media: 30 days default (user-configurable)
    • User Profiles: Until account deletion + 30-day grace period
    • Danger Zone Models: Updated daily, historical kept 1 year

DATA FLOW ARCHITECTURE

    SQLite/Prefs          REST API            Firebase
         ↓                          ↓            ↓
    Offline Queue         Guardian Notify   Analytics Dashboard

7. KEY WORKFLOWS
================================================================================

SOS TRIGGER WORKFLOW
  User presses SOS button (or trigger via shake/voice)
    ↓
  SosCubit.triggerSOS() called
    ↓
  1. Reload emergency contacts from Firestore
  2. Validate contacts exist
  3. Start audio/video recording
  4. Capture initial photo
  5. Enable live location streaming
  6. Send SMS to primary contact (Twilio backend)
  7. Send push notifications via FCM
  8. Optional: Initiate video stream (Agora)
  9. Optional: Auto-call emergency services
    ↓
  Display SOS Active screen to user
  Show emergency contacts & cancel button
    ↓
  User can Cancel SOS or contacts can confirm help status

LOCATION TRACKING WORKFLOW
  User opens app
    ↓
  Request location permissions
    ↓
  Start periodic location updates (every 30 seconds)
    ↓
  Each update:
    - Get current GPS position (geolocator)
    - POST to /location backend endpoint
    - Cache locally (SQLite)
    - Check if in danger zone (AI model)
    - Notify guardians of movement
    ↓
  Continue until app closed or location sharing disabled

PANIC WIDGET WORKFLOW
  Widget added to home screen
    ↓
  User taps panic widget (phone may be locked)
    ↓
  Panic widget service triggers:
    - Save 'panic_triggered' flag to SharedPreferences
    - Post stream event to app
    ↓
  If app is running: trigger SOS immediately
  If app is closed: launch app, check flag, trigger SOS
    ↓
  App checks pending SOS state
    - If user logged in: proceed with SOS flow
    - If user not logged in: attempt Firebase session restore
    - If no session: show emergency mode (reduced SOS)
    ↓
  Execute SOS or guest emergency response

GUARDIAN MANAGEMENT WORKFLOW
  User adds emergency contact:
    ↓
  Enter contact name, phone, email
    ↓
  POST /guardians endpoint (save to Firestore)
    ↓
  Send invite SMS/email to guardian
    ↓
  Guardian receives invite, downloads app
    ↓
  Guardian confirms relationship
    ↓
  Enable live location sharing (user's choice)
    ↓
  Guardian can now:
    - See user's real-time location
    - Receive SOS push notifications
    - Call/message user directly

VOICE DISTRESS DETECTION WORKFLOW
  App running in background (background service active)
    ↓
  Continuous audio streaming from microphone
    ↓
  On-device ML model (speech_to_text) analyzes audio
    ↓
  Model detects distress markers:
    - High-pitched voice
    - Panicked speech patterns
    - Words like "help", "emergency", "stop", "don't"
    ↓
  If confidence > threshold (e.g., 75%):
    - Auto-trigger SOS
    - Alert user with notification
    - Allow user to cancel within 5 seconds
    ↓
  If user doesn't cancel → proceed with SOS workflow
